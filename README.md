# AXIONA Systems Website

Public website source for AXIONA Systems.

https://axiona.systems/

This repository contains the static source and public quality controls required to publish the AXIONA website through GitHub Pages.

## How the site is built (v4)

The public pages are generated by one script from a few data files:

- `scripts/build_site.py` writes every page, the redirects from the old URLs, `sitemap.xml`, `naplo/feed.xml` and `llms.txt`.
- `data/proof.json` holds the receipts and test counts, `data/milestones.json` the Napló milestones, `data/ideas.json` the Ötletláda.
- `assets/site.css` and `assets/site.js` are the only stylesheet and script. Fonts (Inter, JetBrains Mono) are self-hosted and subset in `assets/fonts/`.
- Every page carries a strict Content-Security-Policy (`default-src 'none'`, only same-origin scripts, styles, images and fonts) and a referrer policy. Pages contain no inline styles, scripts or event handlers, so the policy needs no exceptions.

After changing a data file or the generator:

```bash
python3 scripts/build_site.py
```

The generated files are committed. CI fails if they are not up to date.

## Local preview

```bash
python3 -m http.server 8080
```

Then open `http://localhost:8080/`.

## Public repository boundary

Only visitor-facing website source, public quality checks and publication-related configuration belong in this repository.

Internal governance, private infrastructure details, private repository names, credentials, customer data and operational secrets are intentionally kept outside the public repository. `scripts/verify_site.py` fails if a known private name appears in a public file.

### Brand runtime authority

The website is a consumer of the private `axiona-systems/AXIONA_BRAND` authority, pinned at `aebf0f112bd5f4e589ef58f337a55d9be861b493`. Exact runtime provenance and hashes are recorded in `assets/brand/AXIONA_BRAND_RUNTIME_V1.json` and `docs/status/AXIONA_BRAND_CONSUMER_PROVENANCE.md`.

## Quality and release controls

Run everything that does not need a browser:

```bash
bash scripts/verify-all.sh
```

- `scripts/verify_site.py`: generator freshness, sitemap, links and anchors, page head metadata, icons, images, Content-Security-Policy and referrer policy, no inline code, no external scripts or tracking, redirects, 404, private names, data files.
- `scripts/verify_security_txt.py`: RFC 9116 `security.txt`.
- `scripts/verify_retired_routes.py`: retired routes stay retired.
- `scripts/verify_brand_consumer_boundary.py`: brand assets match the pinned authority.
- `scripts/verify_browser_audit_matrix.py`: Lighthouse and axe cover the sitemap.
- `scripts/verify_served_site.py --mode local|live`: the served bytes equal the source.
- `scripts/verify_render_contract.mjs`: every page on desktop and mobile in a real browser, including CSP violations, console errors and external requests.
- `scripts/axe-audit.mjs`: accessibility audit of every page.

Workflows:

- `axiona-repo-guard.yml`: static checks on every pull request and push.
- `axiona-browser-audit.yml`: Lighthouse and axe for pull requests.
- `axiona-render-contract.yml`: served-bytes check and browser render contract.
- `axiona-pages-rebuild.yml`: exact-main GitHub Pages publication and live verification.

GitHub Actions dependencies are pinned to immutable full commit SHAs and validation workflows run with read-only repository permissions. The Pages publisher is the only workflow allowed a Pages write scope.
