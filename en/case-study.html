Method

First the problem must be clear.

The goal is not to build a large system immediately. First we choose one real operational problem.

If the first version helps, it can be extended. If not, it is better to stop early.

First round

The work should move in simple, clear steps.

1. Problem

What takes time? Where is information scattered? What is repeated manually too often?

2. First version

A small internal tool or process improvement is built.

3. Review

We check whether there is less searching, copying or misunderstanding.

What to avoid

A large first version is often slow, expensive and hard to use.

No large platform first

Solve one problem well first.

No unnecessary features

Anything that does not help daily work can wait.

No hidden process

Decision points should remain visible.
